# Задача: реализация Player Ranking в Geometry Dash Demon List

Необходимо реализовать полноценную систему рейтинга игроков (Player Ranking) в существующем проекте Geometry Dash Demon List.

Перед началом работы изучи текущую архитектуру проекта, существующие HTML, CSS, JavaScript и JSON-файлы. Интегрируй функциональность в существующий проект. Не переписывай его с нуля и не ломай уже работающие функции.

# 1. Принцип рейтинга

Рейтинг строится исключительно на основе полных прохождений (100%) уровней из Demon List.

Учитываются позиции TOP 1–150:
- TOP 1–75 — Main List.
- TOP 76–150 — Extended List.

За каждое первое прохождение конкретного уровня игрок получает очки в зависимости от текущей позиции этого уровня.

Процентные прохождения не учитываются вообще.

# 2. Формула начисления очков

Используй экспоненциальную формулу:

P(n) = round(40 + 960 * (23 / 24)^(n - 1))

Где:
- P(n) — очки за прохождение уровня.
- n — текущая позиция уровня.
- Максимальное количество очков — 1000.
- Минимальное количество очков — приблизительно 42.
- TOP 1 — 1000 очков.
- TOP 2 — 960 очков.
- TOP 150 — приблизительно 42 очка.

# 3. Динамический пересчёт

Это одно из важнейших требований.

Очки должны зависеть от АКТУАЛЬНОЙ позиции уровня, а не от позиции на момент прохождения.

Пример:

1. Zoink проходит уровень, находящийся на позиции #1.
2. За прохождение ему начисляется 1000 очков.
3. Появляется новый уровень, который занимает #1.
4. Предыдущий уровень перемещается на #2.
5. Очки Zoink за старый уровень автоматически меняются с 1000 на 960.

При этом:
- Запись о прохождении сохраняется.
- Дата прохождения не меняется.
- Ссылка на видео не меняется.
- Меняется только количество очков.
- Общий рейтинг всех игроков пересчитывается.

Не сохраняй начисленные очки в записи прохождения. Вычисляй их на основе актуальной позиции уровня.

# 4. Правила начисления

Обязательные правила:

1. Учитывать только прохождения на 100%.
2. Учитывать только первое прохождение конкретного уровня конкретным игроком.
3. Повторные прохождения не приносят дополнительных очков.
4. Уникальность определяется комбинацией playerId + levelId.
